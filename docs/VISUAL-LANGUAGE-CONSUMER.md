### Bounded in-repo Portico (reconcile carefully)

PR #5 adds a **bounded `/portico` orientation specimen** (`docs/PORTICO.md`, commits `258fe20..c3f39b7`). `measured` on branch `docs/w2-w3-scope`.

- Portico here is an **orientation / encounter grammar** over existing LithoMemphis routes and **existing tokens/primitives**.
- It is **not** an external Visual OS, not a second material system, and not live collaboration.
- See [PORTICO.md](PORTICO.md) for threshold / gate / trace / torch / stewardship concepts.

### Downstream consumer rule (non-negotiable)

LithoMemphis consumes **only** modules that are:

1. **pre-specified**, 2. **pre-executed**, 3. **proven**, 4. **reusable**, 5. **researched**, and 6. **implementation-derived** —

delivered as drop-in assets, components, scenes, effects, or primitives **with fixture receipts** (§6). No speculative imports. No unversioned shaders. No static AI stills as runtime truth.

### Semantic boundary (Omni-Loom `CONSUMER-MATRIX.md`)

> `stitch_plan.json` fabrication IR ≠ shader optical metadata ≠ visual design tokens ≠ Living Cloth material semantics.

Exchange occurs **only** via versioned envelopes and **loss-aware adapters**. Physical measurements require **explicit units** and measurement provenance (`calibrated` vs `illustrative`). Illustrative artistic sliders are not calibrated physical units. `proposed` classification from recovery pack v3 discovery dated 2026-11-04.

## 4. Interaction translation matrix & implementation rules (v1.1 → v1.2)

Every consumable must declare **bindings** from its state machine to these surfaces — not only how it looks at rest. Align onboarding with Portico’s **orientation-over-instruction** principle ([PORTICO.md](PORTICO.md)).

### 4.1 Six-surface Interaction Translation Matrix

| Surface | Inputs | Print / craft fixture mappings |
|---|---|---|
| **Design (Figma / tokens)** | Static frames, variants, motion specs | Plate wear as token · misregistration as variant · hatch density as density scale · ink set as palette contract |
| **Component (web)** | Hover, focus, press, drag | Lensing on hover · press = plate impression (depressed relief) · drag = ink smear / registration drift |
| **Mobile touch** | Tap, long-press, pinch, pan, multi-touch | Tap = stamp · long-press = ink bleed / Condensation · pinch = hatch density / plate scale · pan = slide-scroll registration |
| **Device motion** | Orientation, tilt, gyro, accel | Tilt = specular / relief catch-light · gyro = parallax cutout layers · shake (rare) = plate knock / dust |
| **Scroll narrative** | Scrollytelling, slide-scroll, scrub | Scroll progress drives Crystal Growth / ink fill · chapter pins = plate changes · scrub = scrubbable press cycle |
| **Onboarding / orientation** | First-run, re-orient, reduced-motion | Teach one phenomenon per beat (stamp → bleed → relief) · gyro optional, never required · always keyboard / screen-reader path · Portico thresholds preferred over instruction dumps |

### 4.2 Eight Implementation Rules

1. **One semantic state machine, many adapters.** Canonical states: `idle | lensing | impressed | bleeding | drifting | reduced`. Web / mobile / scroll / gyro are adapters, not forks.
2. **Progress as a first-class continuous input.** `t ∈ [0, 1]` from scroll, timeline, or gesture; fixtures must be continuous in `t`, not only keyframe snaps.
3. **Input modality contract.** Declare `required` / `enhancement` / `forbidden` per fixture. Pointer ≠ finger ≠ tilt. **Gyro is always enhancement-only.**
4. **Relief & press physics.** Springs model plate impression (`k`, `ζ`, travel in mm-equivalent); release = **ink lift**, not generic bounce.
5. **Registration as layout primitive.** Misregistration Δx/Δy may bind to hover, tilt, or scroll velocity — **clamped**.
6. **Narrative onboarding sequence.** `silhouette → stamp → hatch → relief → optional optics`. Never dump the full SDK.
7. **Reduced motion / reduced sensing parity.** Replace phenomena with deterministic static print states; **zero** essential content that only exists via gyro or scrub.
8. **Viewport classes & LOD contracts.** `phone` · `tablet` · `desktop` · `projector` each declare LOD and touch-target contracts in the fixture receipt.

## 5. Living Cloth & Nacre contracts (ADAPT inventory — not runtime truth)

### 5.1 Living Cloth — observation protocol (`self-reported` attachment, 2026-11-04)

1. Witness without naming (movement, resistance, overlap, repetition, breakage, pressure-change, stillness, delayed appearance).  
2. Separate evidence from inference; preserve confidence, alternatives, missing evidence.  
3. Observe through material, structural, temporal, emotional, communicative, cultural, computational, accessibility, and failure angles.  
4. Map evidence → material / fiber / weave / stitch / pattern / seam / cluster / color / depth / motion / sound / affect / communication / provenance / anti-pattern.  
5. Derive causal relationships, synergies, conflicts, dominance, cancellation.  
6. Calculate stitch count, thread coverage, density, complexity budget, spring / sound / diffusion / negative-space values.  
7. Generate conservative, expressive, and wildcard variants.  
8. Compare against anti-patterns.  
9. Store a decision receipt.

`observe → separate → map → relate → calculate → compose → validate → record`

### 5.6 Equations & clamps (illustrative; unit provenance required before calibration claims)

| Id | Formula | Clamp |
|---|---|---|
| `motion_duration_ms` | `T = 180 + 620*mass + 480*drag + 320*emotional_weight - 210*urgency` | `[120, 2800]` |
| `spring_stiffness` | `K = 80 + 240*(1-material_stiffness) + 180*tension` | `[60, 420]` |

| `complexity_budget` | `B = 1 - (0.22*pattern_count_norm + …)` | threshold `0.18` |

### 5.7 Nacre instrument precedent (optional host pattern)

- Full-screen creative instrument: paint an evolving material, adjust response, inspect, export a **local** session.
- Sculpture = **real procedural mesh + TSL**, not pasted concept art.
- GPU: two storage textures, fixed **30 Hz** simulation; CPU scalar reference fallback with GPU-rendered viewport.
- Session JSON import/export with schema validation; runtime panel discloses mode / renderer / fallback reason.
- `prefers-reduced-motion`: **paused by default**.
- Cross-backend numerical identity and physical optical calibration are **not claimed** unless fixtures prove them. Dawn/SwiftShader probe deltas are research evidence only, not LithoMemphis runtime guarantees.

## 6. Minimum fixture receipt & `DEFER → ADAPT` promotion gate

A module may move from **DEFER** to **ADAPT** only when a receipt ships with **all** of the following. Incomplete receipts stay `DEFER`.

### 6.1 Required fields

3. Parameter schema + clamps + deterministic seed  
4. State-machine map (`idle|lensing|impressed|bleeding|drifting|reduced` + transitions)  
5. Maps / shaders / source + content SHA-256  
6. Golden stills + short motion proof  
7. Input contract (`required` / `enhancement` / `forbidden`)  
8. Progress binding for `t ∈ [0, 1]`  
9. Gesture → phenomenon map  
10. Onboarding beat ID (if taught in orientation / Portico)  
11. Device LOD table (`phone|tablet|desktop|projector`)  
12. A11y / reduced-motion fallback (static print state)  
13. Provenance / chosen-against ledger  
14. `anti_patterns` audit (checked, not aspirational)
